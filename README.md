# binsize

Track binary size regressions with per-package attribution.

"Your binary grew 400 KiB" is not actionable. "`net/http` grew 132 KiB" is.

## Example

```
$ binsize analyze ./bin/app --label cli -o head.json
$ binsize diff base.json head.json
```

Renders as a PR comment:

### Binary size: `cli`

**grew 2.35 MiB** — 1.81 MiB to 4.15 MiB (+129.91%)

## Install

```sh
go install github.com/quantum3ap/binsize/cmd/binsize@latest
```

## Usage

```sh
binsize analyze <binary> [--label NAME] [--symbols] [-o FILE]
binsize diff <base.json> <head.json> [--format markdown|json] [--budget BYTES]
```

Exit codes: `0` ok, `1` error, `2` budget exceeded. Wire `--budget` straight into CI:

```yaml
- run: binsize diff base.json head.json --budget 512000
```

## Supported formats

| Format | Platforms | Symbol sizes |
|---|---|---|
| ELF | Linux, BSD | Exact (`st_size`) |
| Mach-O | macOS | Approximate (address gaps) |
| PE | Windows | Approximate (address gaps) |

Mach-O and PE symbol tables do not record sizes, so they are derived from the distance to
the next symbol and include inter-symbol padding. Attributed totals therefore run roughly
60% higher than ELF for identical source. Deltas stay meaningful; absolute totals do not
compare across formats, and `diff` refuses to try.

## Why the toolchain metadata matters

Binary size is not stable across compiler versions, build flags, runner images or
attribution methods. Diffing a baseline built with `-ldflags="-s -w"` against one built
without it shows a 57% "regression" that has nothing to do with the source.

Every report records compiler, version, build flags, GOOS/GOARCH and attribution method,
hashed into a fingerprint. `diff` refuses to attribute across a mismatch and names the
differing field, rather than reporting confident nonsense:

```
**not comparable** — 1.81 MiB to 2.84 MiB (+57.04%)

> Attribution suppressed: the baseline was built differently
> (build flags "" -> "-ldflags=-s -w"; stripped false -> true).
```

The total is still reported, because file size is always a valid signal.

## Testing

```sh
go test ./...
```

Fixtures are cross-compiled at test time rather than committed, so they always match the
local toolchain and can be regenerated by anyone chasing a parsing bug. Coverage spans
ELF/Mach-O/PE parsing, schema round-trip, the comparability guard, and budget exit codes.
